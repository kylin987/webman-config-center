# 客户端成功认证缓存

用户确认优化每次拉配置重复 password_verify 的 CPU 开销。线上采样已定位 HTTP worker，但尚未取得函数级性能采样。

- 每次认证仍查询 MySQL enabled 账号，返回当次模型并保存 last_used_at。
- 每个 HTTP worker 内存按账号 ID 保存最多一个成功凭据摘要，固定有效期 60 秒，不随命中延长；最多 1024 条，新增满额时淘汰最早插入项。
- 摘要使用进程随机密钥 HMAC-SHA256，输入为当前数据库密码哈希、分隔符、请求密码。缓存不保存明文密码、可用于直接调用 API 的 token 或模型对象。
- 缓存未命中/到期执行原 password_verify，只有成功才写入。改密、禁用、删除、改名通过每次数据库查询及摘要匹配即时生效（与原认证相同，以当次数据库读取为准）。
- 不新增 Redis、表结构、配置项；管理员登录/MFA 不经过此缓存。
- 使用内存 SQLite + 真实 ORM/password_verify 验证账号变化、错误密码、固定到期、容量上限；计数与单调时钟仅由测试命名空间代理观察/推进。
- 基准保持数据库查询/使用时间写入相同，对比原认证与缓存命中路径。本地基准不代表线上整 Pod 降幅。
